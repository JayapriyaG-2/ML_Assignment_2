## a. Problem Statement

The goal of this project is to build, evaluate, and deploy multiple supervised
classification models that predict whether a person has **Parkinson's
Disease (PD)** based purely on acoustic/signal-processing features extracted
from a sustained vowel phonation recording. This is a binary classification
problem — **Healthy (0)** vs. **Parkinson's Disease (1)**. Five
classification algorithms are trained on the same dataset, compared using
six evaluation metrics, and the best-performing model is identified. All
models are demonstrated through an interactive Streamlit web application.

## b. Dataset Description

- **Name:** Parkinson's Disease Classification (speech features)
- **Source:** UCI Machine Learning Repository —
  https://archive.ics.uci.edu/dataset/470/parkinson+s+disease+classification
  (Sakar, C.O., Serbes, G., et al., 2018)
- **Raw file:** bundled in this repo at `data/pd_speech_features.csv`
  (756 rows as downloaded; original file has a 2-row header)
- **Instances:** 756 voice recordings, from **252 unique patients** — 188
  diagnosed with Parkinson's Disease, 64 healthy controls — each patient
  recorded **3 times**, sustaining the vowel /a/. (Satisfies the
  assignment's minimum of ≥500 instances.)
- **Features:** 754 numeric acoustic/signal-processing features per
  recording (satisfies the assignment's minimum of ≥12, by a wide margin),
  grouped into:
  - **Baseline features** — jitter, shimmer, harmonicity, pulse statistics
  - **Intensity parameters** — min/max/mean signal intensity
  - **Formant frequencies & bandwidths** — f1–f4, b1–b4
  - **Vocal fold features** — GQ, GNE, VFER measures
  - **MFCCs** — Mel-frequency cepstral coefficients
  - **Wavelet transform features**
  - **TQWT features** — Tunable Q-factor Wavelet Transform coefficients
  - Plus `gender` (already encoded 0/1)
- **Target:** `class` — 1 = Parkinson's Disease, 0 = Healthy control
- **Class balance:** 564 PD recordings / 192 healthy recordings (imbalanced,
  ~74.6% / 25.4%)
- **Missing values:** none
- **Preprocessing:** All features standardized with `StandardScaler` (fit
  on the training split only, then applied to the test split). `id` was
  dropped as a feature (used only to define the patient-level split, see
  below) and `class` was used as the target.

### ⚠️ Patient-level train/test split (important methodological note)

Because each of the 252 patients contributed **exactly 3 recordings**, a
naive random 80/20 row-wise split would place recordings from the *same*
patient in both the training and test sets. A model could then partly
"recognize" a patient's voice rather than genuinely generalize to unseen
patients — inflating test performance in a misleading way. To avoid this
data leakage, the split in `model/train_models.py` is done with
**`GroupShuffleSplit`, grouped by patient `id`**, so all recordings from a
given patient fall entirely into either the train set or the test set,
never both. This gives a more honest, defensible estimate of real-world
performance — and is worth explicitly mentioning if asked about your
methodology.

- **Train:** 603 recordings from 201 patients
- **Test:** 153 recordings from 51 patients

`test_data.csv` in this repository is that held-out test split (153 rows,
raw/unscaled feature values + true `target` column) — this is the file you
should upload in the Streamlit app to see predictions and metrics.

## d. Models Used

All 5 models below were trained on the **same** patient-level train/test
split of the same dataset, with the same preprocessing pipeline.

| ML Model Name | Accuracy | AUC | Precision | Recall | F1 | MCC |
|---|---|---|---|---|---|---|
| Logistic Regression | 0.8105 | 0.8385 | 0.8868 | 0.8468 | 0.8664 | 0.5428 |
| Decision Tree | 0.7647 | 0.6972 | 0.8319 | 0.8468 | 0.8393 | 0.4006 |
| kNN | 0.8039 | 0.8207 | 0.8140 | 0.9459 | 0.8750 | 0.4596 |
| Naive Bayes | 0.6732 | 0.7120 | 0.8211 | 0.7027 | 0.7573 | 0.2741 |
| Random Forest (Ensemble) | 0.8301 | 0.9186 | 0.8195 | 0.9820 | 0.8934 | 0.5435 |

*(Metrics computed on the 153-row patient-level held-out test set; scores
were generated by `model/train_models.py` and are reproducible with
`random_state=42`. Because the positive class ["Parkinson's"] is the
majority class here [74.6%], plain Accuracy alone is less informative than
AUC and MCC — a trivial "always predict PD" baseline would already score
~74.6% accuracy.)*

### Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Best precision of all five models (0.8868) — when it predicts PD, it's rarely wrong — but with 754 features and only 603 training rows (p >> n), linear separability is a big ask; regularization keeps it stable but its AUC (0.8385) trails the ensemble methods. |
| Decision Tree | Weakest model by AUC (0.6972) and MCC (0.4006) — a single tree overfits badly in this very high-dimensional, relatively low-sample setting, memorizing training-set idiosyncrasies rather than learning generalizable acoustic patterns. |
| kNN | Very high recall (0.9459) — it rarely misses a true PD case — but this comes from leaning heavily toward the majority class in 754-dimensional space, where distance metrics become less meaningful ("curse of dimensionality"); its precision and MCC are correspondingly modest. |
| Naive Bayes | Clearly the weakest model overall (Accuracy 0.6732, MCC 0.2741). Naive Bayes assumes features are conditionally independent given the class — a poor fit here, since many of the 754 acoustic features (e.g. different MFCC/wavelet/TQWT coefficients derived from the same recording) are highly correlated with each other. |
| Random Forest (Ensemble) | Best overall performer — highest Accuracy (0.8301), AUC (0.9186), F1 (0.8934), and MCC (0.5435), plus the highest recall (0.9820) of any model. As an ensemble of many trees on random feature subsets, it handles the high-dimensional, correlated feature space far better than a single Decision Tree, and its bagging naturally guards against the overfitting that hurts the single tree here. |
| **Overall Winner for this dataset** | **Random Forest (Ensemble)** — best across Accuracy, AUC, F1, and MCC, making it the clear, well-rounded choice for this high-dimensional acoustic dataset. |

*(Note: even with the patient-level split preventing direct leakage, 754
features on ~600 training rows is a genuinely hard, high-dimensional
problem — worth mentioning that feature selection/dimensionality
reduction, e.g. PCA or recursive feature elimination, would likely improve
every model here and is a natural "future work" point for your writeup.)*
